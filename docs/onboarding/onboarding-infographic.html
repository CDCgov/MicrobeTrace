MicrobeTrace Developer Guide

AI-Assisted Developer
Onboarding

A governance-first workflow for contributing to MicrobeTrace using AI code generation — no Angular expertise required.

🧠

You're an operator, not a traditional developer.

Your job is to reason about the system, direct AI to generate code, and prove correctness. Deep Angular knowledge is not the goal — understanding MicrobeTrace's data model and verification discipline is.

1

Know the System Boundaries

📡

State Store

CommonStoreService

All components react to these observables. BehaviorSubjects emit state changes. Breaking a subject breaks the entire app.

160 LOC — read all of it
⚙️

Business Logic

CommonService

Filtering, coloring, distance metrics, worker coordination. Where most bugs originate. The main refactoring target.

3,597 LOC — understand what, not how
📊

Visualizations

visualizationComponents/*

13 view components (2D Network, Map, Timeline, etc). Tightly coupled to CommonService. Changes ripple across views.

10,000+ LOC combined
✅

Test Oracle

cypress/oracle/*

Independent computation of expected filtering behavior. Your correctness guarantee. 59 Cypress specs validate against it.

The source of truth

Data Flow — How State Moves

📁 File Upload → ⚙️ CommonService (transform + filter) → 📡 CommonStore (emit state) → 📊 Views (subscribe + render)
2

Every-Task Workflow

1

Propose

Before touching code, define scope.

  • What files will change?
  • What behavior changes?
  • What could break?
  • How will you verify?
2

Execute with AI

Use Codex / Claude to generate:

  • Implementation code
  • Unit tests (required)
  • Edge case handling
  • Explain why output is correct
3

Verify & PR

Prove the change is safe.

  • Unit tests pass
  • 59 Cypress specs pass
  • Manual check documented
  • PR checklist complete

Key Rule

If you can't verify it, it doesn't get committed. Verification is where the real learning happens.

Onboarding Timeline

Week 2–3 — First Extraction

Extract filtering logic from CommonService

Write unit tests for threshold/NN/epsilon behavior, then extract into GraphFilteringService.

Define expected behavior Write unit tests (AI-assisted) Extract service Verify Cypress suite Submit PR with checklist
Week 4+ — Expand

Continue service extractions

Continue CommonService decomposition. Add unit test coverage for each extracted service.

ColorMappingService consolidation MetricsComputeService extraction Unit tests per service
Ongoing

Earn expanded authority

As you demonstrate consistent, verified work — scope expands to visualization components and new features.
